# travel-guide-skill

一个 Agent Skill（WorkBuddy / Codex 通用）：把机票、酒店、逐日行程、美食整理成**手机上能看、能分享给家人**的单文件网页攻略，并发布成链接。

## 它解决什么

做旅游攻略最费时间的不是"想不出去哪玩"，而是：

- 酒店到底哪家划算 —— 含早几份？含不含门票/接送？什么时候前能免费取消？
- 每天几点出发、几点到、哪个环节会卡死 —— 索道 17:00 停售、船票提前 15 天预售、本地小吃 13:00 就售罄
- 怎么把这一堆东西整理成家人愿意看、出发当天能照着走的东西

这个 skill 把整套流程固化下来。

## 六条铁律

1. **先定行程，再做计划书** —— 行程没敲定前不要动手写页面
2. **一天一天确认** —— 不要一次给全套，用户一定会改
3. **数据必须有来源** —— 查不到就说查不到，不要编
4. **兼顾同行所有人** —— 别只顾自己的商务/采购目的，老人小孩的景点和吃饭要一起满足
5. **酒店比"实付含什么"，不比裸房价** —— 含早份数 / 门票 / 接送 / 免费取消截止时间
6. **餐饮不要偷懒** —— 别把三餐全排在酒店

## 六阶段流程

信息收集 → 方案对比（给明确推荐）→ 交通（机票/高铁/接驳）→ 住宿（逐晚定，1 主推 + 1 备选）→ 逐日行程（时间轴 + 三餐 + 备用方案）→ 美食（店名/招牌菜/人均/**营业时间**）→ 落地单文件网页 + 发布

## 取数技巧（实战验证）

| 需求 | 做法 |
|---|---|
| 读用户已订的携程订单 | **`https://my.ctrip.com/` 是唯一稳定入口**；PC 端 `hotels.ctrip.com/hotels/orderlist` 等订单列表页全返回空白页 |
| 拿携程 orderid | 在 `my.ctrip.com` 上找「取消」按钮的 `a[href]`，里面带 `orderid=xxx` |
| 小红书笔记数据 | **不要直连**（未登录 + 海外 IP 报 `300012 IP存在风险`），改走搜索引擎侧聚合 |
| 机票价格 | **移动版页面 + 价格日历**比 PC 端稳 |

## 踩坑清单

- 单次 Write 超过约 60–70KB 会被截断，大 HTML 要分段写并校验尾部
- `cd X && cmd &` 会把 `cd` 一起后台化，脚本一律用绝对路径
- 儿童设施"免费与否"要交叉核实，不同来源经常互相矛盾
- 景点预约类硬约束（摇号/预售/停售）单独列清单

## 用法

把整个目录放进 agent 的 skills 目录（如 `~/.workbuddy/skills/`），或直接把 `SKILL.md` 交给 agent。模板改 `DAYS` 数组即可复用整套视觉。
